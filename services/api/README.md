# 业务服务任务

主责仓库负责人。此目录尚无真实服务实现。先确认平台原生能力是否足够。确需自建服务时建议单一 Node.js 服务加 SQLite（部署须有持久卷），只实现必要会话、平台转发与任务记录；具体框架由负责人选择并锁定依赖。无需开发正式注册体系、微服务或管理后台。

数据对象：服务端会话、任务实例、积分流水、主动建议开关、最少事件记录。长期记忆后置。浏览器发业务事件，服务校验身份/授权与字段，再调用 GeniOS；模型只能选择许可的任务模板，积分按服务端固定表结算。

API 形状见 `contracts/README.md`。模拟服务只是独立开发工具，不能复制为生产鉴权/持久化实现。真实服务从安全会话凭据确定主体，不接受可任意指定的 user_id；跨用户资源检查必须覆盖读取和写入。

任务完成需校验开始时间和状态，在事务内唯一结算；使用 Idempotency-Key 保障重试；同 key 不同负载返回 409。AI 故障不回滚已确认的任务和积分；后续文案可重试。

GeniOS 适配器先用 fixtures；C 提供真实平台文档/脱敏调用后再写 endpoint、鉴权和响应转换。不得假定公网 Coze API 与 NK-GeniOS 通用。密钥只在环境变量；请求日志去掉用户原文和令牌。

本轮不实现跨会话长期记忆，remember 只接受 false。若后续扩展，再按用户隔离、单独同意、可撤回删除设计，不假定平台原生支持。首版不需要自动读取教务课表。发布前验证持久化、HTTPS、错误恢复和不同会话隔离。
