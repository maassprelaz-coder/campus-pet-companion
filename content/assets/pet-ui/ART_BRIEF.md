# 校宠伴行 · 网页宠物美术需求单（v1，2026-10-16）

给美术同学的一份可照做清单。**只覆盖网页当前流程需要的画面**，不做完整美术体系，不新增手机 App 或桌面打包。接入由 B（网页）负责，本单里的文件一律放到 `content/assets/pet-ui/`。

## 0. 背景（一句话）

网页主流程是：**选场景 → 聊天 → 宠物给建议 → 用户接受/拒绝 → 完成任务 → 宠物反馈**。宠物动作要和智能体返回的动作枚举一一对应，才有"情境化宠物反馈"的展示效果，所以**动作名不能自己起**。

## 1. 必须做（核心，16 日）

### 1.1 宠物动作 —— 1 只宠物 × 7 个动作

文件名里的动作键必须与下方完全一致（这是接口白名单，改了就接不上）：

| 动作键（必须用） | 含义 | 建议画面 |
| --- | --- | --- |
| `idle` | 待机 | 呼吸、眨眼，安静循环 |
| `happy` | 开心 | 跳跃、摇尾 |
| `think` | 思考 | 歪头、冒问号 |
| `sleep` | 睡觉 | 闭眼、Zzz |
| `eat` | 吃饭 | 进食 |
| `roll` | 打滚 | 翻滚 |
| `sad` | 伤心流泪 | 垂耳、泪滴 |

规格：

- 画布 **512×512**；角色居中，**脚底基线在所有动作里固定在同一个位置**（否则切换动作时会上下跳）。
- **透明背景**，边缘干净；不要硬投影。
- 动画 8–16 帧、8–12 fps、1–2 秒无缝循环。
- **动态 WebP 优先**（体积小、支持半透明）。GIF 可作兼容备份，但 GIF 只有 1 位透明、边缘易发白——网页宠物区底色是很浅的 `#fbfcfe`/`#f2fbf5`/`#f3f6ff`/`#fdf3f3`，白边影响不算大，但仍建议 WebP。
- **单文件 ≤300 KB**。（参考：旧素材 GIF 单个 0.8–4.7 MB，严重超标，所以这次请按预算压。）
- 命名：`pet-<种类>-<动作>.webp`，例如 `pet-dog-happy.webp`、`pet-dog-idle.webp`。

可选加分：再做**第 2 只**宠物的同一套 7 个动作（用于"领养/切换形象"演示）。**不要一次做 4 只**，先把 1 只做完整。

> **2026-10-16 更新（B）**：旧原型素材库已有 4 只 × 7 个动作 = 28 个 GIF，动作名与白名单完全对应、画风统一、真透明底，**已全部转码接入网页**（见 `tools/convert-legacy-pets.py` 与 `source-register.csv`）。因此**第 1.1 项不再需要外部美术产出**——保留下面规格只是为了日后替换画风或补新动作时有统一口径；若要新做，请只做**矢量/分层源文件 + 同一基线**的 512×512 透明动画 WebP。

### 1.2 宠物主图（1–2 张）

1024×1024 透明 PNG/WebP，≤400 KB，用于首页/领养展示与截图。命名 `pet-<种类>-main.png`。

### 1.3 favicon（1 套）

512×512 PNG，另导出 180×180、32×32，≤50 KB。命名 `favicon-512.png`。

> **2026-10-16 更新（B）**：已由 `tools/convert-legacy-pets.py --favicon` 从 `pet-dog-idle.webp` 首帧裁切生成 `apps/web/favicon.png`（512×512 透明调色板 PNG，27.8 KB），页面 `<link rel="icon">` 已引用，**此项无需外部美术**。若日后换形象主视觉，重跑该命令即可。

## 2. 二级（有收益，17 日前；不能挤掉真实试用和材料时间）

- **场景背景 4 张**：宿舍 `dorm` / 图书馆 `library` / 操场 `sports` / 食堂 `canteen`。1600×900，WebP 或 JPG，**≤200 KB**，命名 `scene-<scene>.webp`。要求：简洁插画风格，**不要用真实照片**（避免来源与授权问题），并且白色 UI 面板压在上面时画面仍要清楚。
- **拍立得相框 4 款**：1080×1440 透明 PNG，≤300 KB，命名 `frame-01.png` ~ `frame-04.png`，用于可选的"虚实合拍"。

  > **2026-10-16 更新（B）**：旧原型有 4 款相框（`legacy/prototype/拍立得相框/001–004.PNG`），实测为竖版 5:8、四角与中心均透明（透明像素占 61–64%），与 512×512 正方形宠物贴图不匹配，且本轮网页没有相机/合拍流程（摄像头只做"拒绝授权"演练），**本轮不接入**。若日后做"虚实合拍"，请提供**方形照片窗口（1:1）**版本，或明确窗口在画面中的坐标，B 才好做叠加。
- **空状态小插画 2–3 张**（等待中 / 暂无建议）：800×600 PNG，≤200 KB，可选。

## 3. 明确不做 / 风险项

- **地图**：不要用旧 `map.png`（10.9 MB，且地标未经核实）。若确实需要，只做**"示意图"**（2000×1400 WebP，≤500 KB，画面标明"示意图，非精确导航"），校园事实由 A 核对。**默认不做。**
- **音频/BGM**：默认不做。旧的两个 `.ogg` 来源不明，按提交清单必须移除。若要音效：须原创或明确授权，且 ≤100 KB/个。
- 3D / 写实渲染、桌面或手机 App 图标包、雪碧图大图集：**不做**。

## 4. 风格约定（务必统一）

- 2D 扁平或轻拟物，圆润、治愈系；不要写实照片拼贴，不要 3D 渲染。
- 配色与网页保持一致：主色 `#2f6fed`、成功绿 `#15803d`、提醒橙 `#b45309`、错误红 `#b91c1c`、浅底 `#f6f8fb`、白面板 `#ffffff`、文字深灰 `#1f2733`、次要灰 `#5c6b7f`。
- 宠物会放在很浅的底上，所以**描边要够清楚**，不要用接近白色的描边。
- 同一角色的所有动作：**同画风、同比例、同基线**。
- 不要图片内嵌文字、水印、品牌 logo 或第三方素材拼贴。

## 5. 交付方式

- 交付的源文件放 `content/assets/pet-ui/`；**网页运行副本由 B 转码后放 `apps/web/assets/pet-ui/`**（本地静态服务器只服务 `apps/web` 目录，放两份会重复约 1.6 MB）。
- 每个文件在 `content/assets/pet-ui/source-register.csv` 里加一行（表头固定）：

  ```csv
  asset_path,author_or_owner,source_url,license_or_permission,verified_by,status,notes
  pet-ui/pet-dog-happy.webp,（作者/团队名）,（可留空）,原创并授权本项目使用,B,待接入,512×512 12帧 240KB
  ```

- 请同时口头/文字确认：**是否原创、是否允许本项目在参赛材料和演示中使用**。来源不明或无法确认授权的素材，一律不进仓库、不进提交材料（提交清单有这一条硬要求）。
- 建议另附分层源文件（.psd/.ai/.kra），由 B 单独保管、**不放仓库**（仓库和提交材料有体积限制：支撑材料 PDF/ZIP 合计 ≤100 MB）。
