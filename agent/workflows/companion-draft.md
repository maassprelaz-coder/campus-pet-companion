# 情境陪伴工作流草案

设计状态，尚未在 NK-GeniOS 执行。节点类型与工具能力由 C 在真实平台确认。

1. 输入：事件类型、文本、手动场景、用户自报状态、主动建议开关、由业务服务筛选的授权摘要和可用任务模板。
2. 检查：必要字段、权限和风险；信息不足时追问；风险场景进入支持分支，不发游戏任务。
3. 判断：普通倾听、校园事实查询、专注/放松建议、任务完成反馈。使用明确上下文决定，不把简单随机回答当策略。
4. 检索：涉及校园事实时查已核实知识库；结果不足说明未知。
5. 生成：短回复、许可动作、策略名、一个可选任务模板、来源。格式见 contracts 中的内部模型约定。
6. 业务校验：API 服务校验结构、来源与允许的模板，生成 suggestion_id 和上下文一致的会话标识；模型不结算积分。
7. 用户选择：接受/拒绝；接受后服务建立任务。完成通过服务校验再形成 task_completed 事件，触发反馈。

平台不支持某节点时记录实际替代实现及边界；完成记录、授权记忆和积分由业务服务负责，不预设平台原生数据库或永久记忆功能。
