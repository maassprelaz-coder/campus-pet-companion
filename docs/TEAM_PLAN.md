## 平台集成的决定点

首要风险不是页面制作，而是 NK-GeniOS 的账号权限、真实调用方式和评审访问方式。C 在第一天必须拿到证据。

- 若开放外部调用：网页 → 业务服务 → NK-GeniOS；所有密钥只在服务端，网页对齐本仓库接口。
- 若仅有平台发布页：先确保平台内完成可验证的情境判断、建议和后续反馈；B 的宠物网页可作为补充展示，但两者未贯通时必须如实说明。A/C 当天向主办方确认这种提交形态和平台内持久状态能力；若无法满足核心闭环，继续解决权限或缩小承诺，不能拿假回复冒充接入。
- 若发布链接对非开发者不可用：立即处理校内认证/评审权限，优先于动画和装饰。录屏只能辅助，不能替代所要求的 URL。

## 不同时间工作的交接方式

每人用自己的功能分支和小 PR；不需要约同一时段写代码。每天至少更新一次 [当前进展](STATUS.md) 中自己对应行，或在 PR 中记录：“完成什么／怎样运行／自测结果／等谁给什么／下一步”。超过半天的阻塞写清具体缺口和替代工作，其他人可异步回应。

推荐合并次序：接口草案确认 → 各模块最小版本 → 真实平台联通 → 任务闭环 → 必要权限/失败处理 → 材料。A 每天固定一到两次集中检查合并，功能模块各自负责修复，不要求三人在线开会。

完成标准：不仅是推了代码，必须有可复现运行方式、对应验收结果和可交接产物。每个人保留自己的提交和演示记录；不伪造 Git 提交身份或测试结果。
