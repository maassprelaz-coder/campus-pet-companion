# 参赛范围与验收

目标是按[比赛评分](SCORE_PLAN.md)争取高分。下面是团队实现建议，不是比赛强制功能清单。旧项目可选择性复用；不以复用比例或功能数量衡量成果。此轮只修订计划。

## 必须交出的核心效果

| 效果 | 建议实现及已有基础 | 验收证据 |
| --- | --- | --- |
| 可理解的校园陪伴入口 | 旧宠物、宿舍和场景页可用则改造，体验差则局部替换；优先浏览器或平台原生入口 | 非开发者能找到聊天、建议与任务；文本安全显示；基础操作无需摄像头/定位 |
| 真实情境决策 | GeniOS接收明确输入、场景和可信任务状态；必要时检索校园知识 | 三种情境对照说明决策区别，来源可核查，未知信息能澄清 |
| 适度主动服务 | 应用内场景进入、任务完成等事件触发建议或反馈，考虑用户拒绝和频率 | 可关闭，不重复打扰；记录真实触发和抑制效果，不夸大自动感知能力 |
| 一个完整行动流程 | 旧专注计时/任务是候选，选最符合需求且能可靠完成的行动 | 建议→接受/拒绝→任务状态→真实完成→反馈；刷新与重试可恢复 |
| 可靠状态与最少数据 | 平台能提供就使用，缺失再补服务；积分按确定规则，可不做完整奖励体系 | 未到时/未接受不算完成，重复不多奖，跨使用者不能读写对方数据 |
| 可访问的真实智能体 | 实际发布的GeniOS URL；必要网页与之真实联通 | 按评审条件由非开发者和另一设备验证，视频/链接同版本 |
| 实施成效和提交证据 | 16日起真实自愿试用，17日固定材料 | 实际人数、流程结果、等待时间和失败可追溯；配置、PDF、视频、截图齐全 |

三情境和“一条先做好”是团队安排。`focus_25`、`relax_2` 是草案样例，不代表两项必须同时实现。真实服务只允许已经接通的模板；先对齐白名单，防止智能体推荐网页没有的任务。

## 有价值的改进可以做

宠物动作与情境一致、校园知识引用、手势合拍、场景视觉、简短成长/装扮、额外行动或偏好记忆，均可按实际收益进入范围，详见[候选与决策办法](SCORE_PLAN.md)。已有且稳定的功能不必为了精简刻意删除；代价高、展示价值低的部分也不必勉强修复。每项写评分价值、展示证据、耗时、依赖和撤回条件。

当前记忆接口关闭，不宣称已支持长期记忆。若试用表明值得做，A先确认平台、授权与删除方案，再共同更新契约、页面和验收；不是永久禁止增强功能。17日优先修复与材料，新增内容不能挤掉真实试用或破坏核心链路。

## 明确边界

不新增手机App、桌面打包和商店发布等题外工作。无需为展示再造完整注册体系、商城或多服务系统；是否增加能力由收益和时间决定。心理诊断、虚构成效、未授权的数据收集不属于本项目的陪伴目标。

原型有待处理的浏览器Electron调用、输入草稿自动发模型、客户端账号/积分、文本HTML插入等问题。A/B只迁移或改写实际采用的部分，原始文件与历史副本保持只读。技术栈不强制锁死；重写要比修补有明确收益，而不是为了更换框架。功能存在、模拟通过、真实联通和已提交分别记录。
