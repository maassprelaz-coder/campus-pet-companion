# 第一版范围与验收

目标是在可核实的 2026-10-18 截止前交付完整、可体验的校园陪伴智能体。以下是团队建议范围，不是比赛逐项规定。

## 必须先跑通

| 功能 | 实现范围 | 验收 |
| --- | --- | --- |
| 宠物与宿舍 | 先接一只宠物，纯文本回复配白名单动作 | 刷新后基础状态可恢复；用户和模型文本不能作为 HTML 执行 |
| 情境输入 | 用户主动选择宿舍/图书馆/运动场；自述近况；拒绝可选授权仍可使用 | GeniOS 收到正确事件和场景；不会偷偷上传输入中的草稿 |
| 智能建议 | NK-GeniOS 依据输入选择陪伴/专注/放松/澄清；必要时查知识库 | 同一框架支持至少三种情境；能拒绝建议、澄清信息不足和标注资料来源 |
| 行动任务 | 先实现专注 25 分钟、放松 2 分钟两种；动作可演示，实际计时不伪装 | 接受→进行中→完成；业务规则核验；重复完成不重复加分 |
| 后续反馈 | 完成事件触发宠物鼓励；AI 失败不撤销已完成任务 | 反馈对应任务；网络失败可重试且不重复奖励 |
| 会话与数据 | 使用平台认可的会话或轻量服务会话；本轮长期记忆关闭 | 不信任客户端传入的 user_id；不同会话互不可读取；不收集多余身份或历史 |
| 评审入口 | 平台真实发布链接，必要时加网页入口 | 非开发者账号能按说明访问；视频演示与链接是同一功能版本 |

## 有余力再做

手势合拍、第二种宠物、食堂知识问答、更完整成就和装扮。手势与合拍虽有代码，外部脚本加载、摄像头授权和真实设备效果仍需验证。其优先级低于真实 GeniOS 接入和任务反馈。

## 本轮后置

手机 App、Electron 桌宠打包、正式账号注册体系、跨会话长期记忆、完整商城、精确 GPS 自动签到、自动读教务课表、心理诊断、复杂推荐训练、多智能体编队、长期后台推送。既有愿景可以写未来计划，但不能在演示或成效里记为已实现。

## 已有原型的具体迁移风险

已读 `legacy/prototype/app.js`、`index.html`、`main.js`、`preload.js`。原型实际是原生 HTML/CSS/JS 和 Electron 壳，不是 React 项目。旧版有前端模型密钥（复制时已清空）、输入即向模型发送日记草稿、客户端明文账号、innerHTML 插入用户文本、客户端积分结算、重复积分 IPC 和浏览器中的 Electron require。先由客户端负责人挑选页面和素材迁移到 `apps/web/`，由后端负责人重建模型请求与结算；不直接原样上线。

不要本轮整体重写成 React，也不要三人同时修改旧 `app.js`。模型输出只允许已定义的宠物动作和任务模板，不能运行模型生成的脚本。
