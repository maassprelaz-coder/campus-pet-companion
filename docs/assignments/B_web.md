## 先做什么

1. 15日首轮看[旧项目评估](../EXISTING_PROJECT.md)，在自己的apps/web中验证值得用的页面和素材；原件与legacy只读。旧宠物、宿舍、专注、任务和合拍已有代码，但运行未验收；给A一份能用/有问题/拟保留或替换及接口缺口清单。
2. 同时核[比赛依据](../REQUIREMENTS.md)与飞书提交全文，确认18日具体截止时刻、入口、申报模板和访问要求。读取不到就写未核实并告诉A，不能默认午夜。首次核对与清单维护归你，账号或报名资料需要A提供。
3. 根目录npm run mock，结合contracts样例先做页面，不等真实平台。当前mock支持本地5173端口；页面保留模拟标识。A交接口后改配置接真实服务，你不自己猜平台API。

## 再具体完成什么

4. 做好清楚的宠物/场景入口、文字输入、回复、建议选择、动作和来源展示。旧页面好用就改造，替换更有收益也可以；不额外做App或桌面安装包。基本回复直接可读，不让旧翻译扣币挡住交流；用户和模型文本不当HTML执行。
5. 接受建议才发起任务，拒绝不创建；显示A确认的状态和时间，刷新可恢复，页面不自行加积分。处理等待、无建议、失败、重试和主动建议关闭。定位/摄像头拒绝仍可用基本功能，不自动发送草稿。
6. 自己盘点宠物动作、背景、相框和地图。保留质量与许可明确的资源，缺口用简单可用素材补齐；记录尺寸、用途、作者/来源/许可。校园事实向A核对，不把旧地图当已确认准确。先做好当前流程所需画面，不重建全套美术。
7. 15日先搭材料提纲，16日真实联通后组织自愿试用，A也可以找人。记录匿名人数、日期/版本、完整流程是否成功、失败步骤、等待时间和反馈。人数按实写；找不到外部试用者就如实写开发自测及局限，不能编造试点。技术问题给A，页面问题自己修。
8. 17日收A的技术证据，整理作品介绍PDF、实际截图、MP4和支撑材料；A审核并最终提交。你不用猜模型、API和工作流：让A交准确文字和配置。签字身份文件单独交授权入口，不入代码仓库。
9. 核心稳定后选择最有评分收益的视觉、合拍或宠物反馈增强，先验证一个，再考虑增加；可以复用也可以新做，但不能挤掉试用、材料和稳定性时间。18日配合最终核对和修复。

## 完成标准

另一位使用者能进入、描述情况、接受或拒绝建议、完成行动并看到反馈；刷新、失败、关闭建议和权限拒绝有可理解表现。素材实际加载正常、来源清楚；材料与真实版本一致。录屏可剪去长任务等待并注明时间跳转，不以加速或mock即时完成冒充真实成效。

现有通知要求MP4≤10分钟且≤500MB、支撑材料PDF/ZIP总≤100M；按[提交清单](../submission/CHECKLIST.md)准备，最新通知有变化须附原文依据。三种情境只是测试设计，不要求再做三套页面。
