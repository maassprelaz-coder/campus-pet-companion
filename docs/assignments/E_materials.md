# 校园资料与展示材料同学的任务

**你负责把校园图片和可靠资料找齐，组织几位同学实际试用，再把开发同学提供的截图、录屏和结果整理成比赛要交的材料。**

你主要负责“内容有依据、效果有记录、提交不漏项”。先确定这版做哪个校区、哪些场景，再有针对性地找资料，不需要整理全校所有信息。

## 具体要做什么

1. 核对提交原文、入口、10 月 18 日的具体截止时刻、申报书和承诺书模板。飞书全文在本次自动读取时跳转登录，当前仓库只核实了已有 PDF 和用户提供的截图部分。
2. 收集所选校区的场景图片或地图，标注来源和使用许可；先问 Seventy 需要哪些，再整理文件。
3. 整理少量可靠校园事实，例如相关场馆或活动规则。每条附适用校区、官方来源和核对日期，交给张祺昌做知识库。先有 10–20 条可用内容即可，这是建议数量，不是比赛规定。
4. 系统能运行后，邀请愿意参与的同学实际体验。记录他们是否完成流程、哪里出错、用了多久和有什么反馈；匿名整理，实际测了几人就写几人。
5. 收齐三位开发者的实际截图、模块录屏和配置说明，按 [提交检查单](../submission/CHECKLIST.md)整理作品介绍、视频和支撑材料。申报书签字扫描件交给负责人按比赛入口提交，不放到代码仓库。

## 怎么交接

校园图片放 `content/assets/campus/`，知识事实填 `content/knowledge/source-register.csv`，匿名试用记录参考 `content/pilot/record-template.csv`，材料草稿放 `docs/submission/`。不会用 Git 可交整理好的文件夹，由负责人入库。

## 最后交什么

有来源的校园图文资料、真实试用记录、对齐实际功能的介绍文档和视频素材，以及逐项核对过的提交清单。技术是否实现由开发同学确认，不需要你猜；没有完成的功能和没有测出的数据不能写成成果。

## 时间安排

10 月 14 日先核对赛务并交第一批资料；15 日补知识和图片；16 日组织试用；17 日完成材料初版和彩排；18 日帮助负责人核对附件和保存提交回执。
