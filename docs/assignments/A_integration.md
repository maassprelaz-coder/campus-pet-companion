# 你负责：接通完整流程、合并与提交

**你要把大家做的东西接起来，让用户真的收到 GeniOS 的建议、选择做或不做、完成行动并得到宠物反馈，再把这个版本按比赛要求交上去。**

你负责连接与统筹，不承担另外四人的全部开发、测试和材料。按[评分计划](../SCORE_PLAN.md)，先确保真实平台和完整体验，再为实施成效与展示留出时间。旧项目能省时、能改善效果的部分才复用。

## 先拿什么，怎样独立开工

读[已有项目评估](../EXISTING_PROJECT.md)、[接口草案](../../contracts/README.md)和[平台确认单](../../agent/PLATFORM_CHECK.md)。先用合成样例确定最少的数据流，B检查旧页面、C核实平台时，你不必等待。

首次交接最迟15日上午：B给旧任务、动作和页面缺口；C给真实调用/发布资料或不支持的证据。没有平台实证时只完成适配边界，不写猜测的校园平台接口。若平台自带界面和工作流足够完成主线，直接减少自建服务。

## 具体要做什么

1. 确定一条能体现校园价值的完整行动流程。现有专注计时与任务奖励是优先评估对象，但不是强制选项；记录旧 `pomodoro`、新 `focus_25`、宠物动作与奖励规则如何对应。不要把旧前端传入的奖励金额当可信业务规则。
2. 同B/C核对并登记接口版本：输入是什么、GeniOS返回什么、接受后如何查任务、完成怎样反馈。样例中的 `relax_2` 不代表必须再造一个任务。需要改字段时你维护公共契约，通知消费者并补样例。
3. 仅补齐必要连接与状态：会话、GeniOS适配、用户接受后的任务创建、查询/刷新恢复、完成记录。采用积分时规则由可信服务或平台工具核验；不用积分也可以交付明确的成长反馈，不必为得分硬建商城。
4. 针对选定流程处理重复请求、任务时间、不同使用者的读写隔离、平台失败。任务已完成但文案生成失败时，保留完成结果并允许重试反馈。模型只能推荐已经实现的任务，不能决定权限、奖励或执行任意代码。
5. 给B一份可复制的真实请求样例和可配置服务地址。模型密钥留在受控服务端或平台配置，不进入浏览器、日志或仓库。平台不支持外部调用时，当天与C改用可实现的形态，并同步B；两套没有连接的页面不能算集成完成。
6. 合并B/C经过各自自测的成果，协助E在16日开始真实体验，按问题影响排序修复。17日登记代码提交、平台版本、入口和配置条件；审核E整理的文件，18日提前提交并保留回执。具体截止时刻由E核实，不能默认午夜。

## 你改哪里，交给谁

主责 `services/api/`、`tests/integration/`、`docs/release/`；维护公共 `contracts/` 和根配置。B负责页面，C负责平台，不同时改他们的实现。每次成果更新[你的交接记录](../handoffs/A/current.md)。

| 时间 | 接收者 | 必须交付 |
| --- | --- | --- |
| 14日或最迟15日上午 | B/C | 核心行动、采用路线、接口版本、旧规则映射及已知限制 |
| 15日 | B | 服务地址/启动方法、配置项名称、会话及接受/查询/完成例子、错误样例；注明mock或真实 |
| 16日 | E及全员 | 可试用版本、最短操作步骤、已知问题、可匿名记录的结果和耗时定义 |
| 17日 | E | 固定入口与版本、联通和可靠性结果、提交检查结果 |
| 18日 | 全员 | 实际提交状态与回执；未提交不能标完成 |

## 怎样算完成

另一个人能按说明从真实GeniOS建议走到接受、完成和反馈；拒绝时不创建任务；刷新可恢复；重复完成不重复奖励；未完成状态不能提前结算；不同会话不能读写对方任务。记录真实等待时长和失败，不把mock测试当真实平台验证。

这些检查由A覆盖服务、B覆盖页面、C覆盖平台，E组织非开发者体验。详细接收标准见[交接明细](../HANDOFFS.md)，不要把全部验收压在最后一天。

## 可加的改进与Codex开工

按评分收益评估成长反馈、额外任务或偏好记忆；有用户需要、实现路径和验证时间再加入，必要时替换低收益工作。当前契约 `remember=false`，这是现状约束；扩展须同时改授权/删除规则、接口和验收，不能只改提示词。无需新增手机App或桌面打包。

把[Codex开工说明](../CODEX_START.md)和这张卡交给你的Codex，补充：“我是A。先说明你要接通的完整流程和采用依据，查旧规则与真实平台交接；只改A的目录和协调后的公共接口。若本次仅审查计划，就只给出计划修改，不启动产品开发。完成后更新A交接记录。”
