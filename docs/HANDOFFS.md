# 交接明细

交接完成的标准是接收者能继续工作。只发一句“写好了”或一个没有说明的压缩包，不算完成。每岗用自己的docs/handoffs目录记录，避免五人改同一个进度文件冲突。

## 冻结与变更

contracts v0.1目前是可用的协作草案，不是NK-GeniOS接口规范。首次看过旧代码和真实平台后，A登记当前采用的接口版本。B/C只针对自己消费者/生产者角色检查字段，不在私下另建相互不兼容的数据格式。

需要改字段时，在本岗记录写“原因、旧/新字段、影响谁、替代样例、切换时间”，A更新公共契约，B/C随后同步。改进已获用户原则授权，正常取舍不需反复问用户；涉及未经授权的账号操作或外部发布仍按具体授权执行。

## 平台不支持外部调用时

C最迟首次交接明确说明。A/C评估平台内是否能完成情境决策、用户选择和后续反馈，并确认提交体验形态；B把工作缩到真正能接上的界面或演示呈现。两套未连接的产品不能宣称已集成，mock不能代替真实平台。无法满足硬要求时记为阻塞，优先解决权限，不能让三人各写三天后再发现接不上。

## 每份交接记录格式

```text
任务ID与负责人：
版本/分支/提交或平台版本：
完成了什么，哪些仍只是计划：
怎样启动或打开（不含密钥）：
按什么步骤得到什么实际结果（注明mock或真实平台）：
文件路径、截图/录屏及来源：
交给谁，对方现在能做什么：
需要谁提供什么、最晚何时需要：
遗留问题及下一步：
```

真实日志只留必要、匿名信息。校园密码、模型密钥、私密日记和签字身份材料不入库。
