## 必须落实的要求

R2 截图原文：

> 作品须统一基于南开大学 GeniOS 平台开发，搭建完整智能体；
>
> 应明显区别于单纯问答型大模型，体现自主感知、智能决策、主动服务等特性；
>
> 必须填写“智能体URL”字段（确保评审可直接点击体验）；
>
> 在“支撑材料”中附上：智能体配置说明、提示词体系、知识库/工作流编排文件等；
>
> “效果演示图”字段上传智能体界面截图或效果演示图。

对应交付：真实平台智能体及可访问链接、实际提示词版本、工作流说明或真实导出文件、知识库来源清单、实际运行截图。平台无法导出时先保存配置截图和逐节点说明，再向组织方确认接受形式；不能把自行写的 JSON 草案当作平台导出。

R1 第 3 页通用材料：申报书及承诺书（负责人签字 PDF 扫描件，有需要时盖章）；作品介绍 PDF（名称、3–5 个关键词、概要、痛点、创新点、落地场景、应用成效）；演示视频 MP4（≤10 分钟、≤500 MB）；支撑材料 PDF/ZIP（总大小≤100 M）。通用清单把支撑材料标为选填，但 R2 软件赛道具体要求明确“附上”配置等，故本项目按必备准备。

R1 第 4 页评分：场景应用价值 20、技术实现规范 25、创新性与扩展性 20、实施成效 20、文档展示与推广 15。实施成效要求有真实落地或试点验证，数据可量化、成效可核查。测试人数、通过率和改善幅度只能填写实际结果。

## 据此提出的工程建议

1. 场景进入、用户明确输入、任务完成是首版的感知输入；不需要为了“感知”额外做情绪摄像头或持续定位。手动输入的感知程度及评审口径仍可向主办方确认。
2. 使用 GeniOS 工作流完成策略选择、知识检索与可执行建议；业务服务负责任务状态与积分，体现明确的人机协作。
3. 主动服务先用应用内进入场景后的建议、任务完成后的反馈，设置关闭开关和频率限制。不是无人授权的后台监控。
4. GitHub 仓库地址、设计稿、离线视频或本地模拟服务均不能替代智能体体验链接。
5. 当前准备的是作品交付，区别于先前报名阶段仅填写项目简介与技术概述。

仍需资料协助者核对：飞书全文、最终提交入口、准确截止时刻、申报模板、评审账号及校外访问方式、作品是否允许使用已有团队原型。已有原型只算基础，本届新增的 GeniOS 工作流、任务反馈和权限隔离需留下真实开发记录。
