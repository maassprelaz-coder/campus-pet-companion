# 网页端取舍记录（B）

记录 2026-10-15 建 v1 骨架时做的决定与理由。改动公共接口或契约前先同步 A。

## 技术选择

1. **不引入框架，继续用原生 HTML/CSS/ESM**。理由：旧原型就是原生 HTML/CSS/JS，页面规模小；加构建链会占用 16–18 日的试用与材料时间，也增加 A 的复现成本。页面拆成 `app.js` + 两个 `lib/*.mjs` 模块，用 `node --test` 直接测，无需打包。
2. **服务地址可配置但默认 mock**。`config.json`（gitignore）> 页面输入框 > 默认 `http://127.0.0.1:8787`。A 交 live 地址后只改配置，不改页面代码。
3. **自己写本地静态服务器**（`dev-server.mjs`）。理由：只需固定 5173（mock 白名单）、只监听 127.0.0.1、能被测试 import 复用；不引第三方 dev server，避免新依赖。
4. **数据只在内存和 `localStorage`**。会话 id 与当前任务 id 存本地，刷新后可恢复任务状态；不建数据库，长期记忆不在本轮范围。

## 契约与安全

5. **只发契约允许的字段**，`preferences.remember` 硬编码 `false`；场景限定 `dorm|library|sports|canteen`；事件类型限定 `chat|scene_enter|task_completed`。多一个字段就可能被服务端 400，早点对齐比事后放宽安全。
6. **幂等键由业务 id 推导**：`event:<event_id>`、`accept:<suggestion_id>`、`complete:<task_id>`。重试和 401 重发用同一个键，服务端只做一次副作用。
7. **401 自动重建会话后原样重发**。避免用户看到假失败；重建会换 `X-Demo-Session`，任务归属随之改变，因此刷新恢复失败时页面明确提示重新开始，而不是假装任务还在。
8. **拒绝建议不调任何接口**，只在页面记录"已拒绝"；页面从不自行加积分，积分只显示服务端返回的 `points_awarded`（mock 恒为 0 并带警告文案）。测试里专门断言了这两条。
9. **文本一律 `textContent` 渲染**（`page-safety.test.mjs` 断言），模型和用户输入不当 HTML 执行；`source.url` 只有 `https://` 开头才渲染成链接。
10. **权限拒绝照常可用**：定位/摄像头/通知被拒时只降级对应功能，基本聊天与任务不受影响；页面不自动发送草稿，必须用户点发送。
11. **记忆接口关闭**：本轮没有任何 `/api/v1/memory` 调用；测试里显式验证该接口返回 501 且不可重试，防止后来者误以为已有长期记忆。

## 宠物贴图与素材（2026-10-16）

12. **复用旧原型素材，不重新找图**。仓库 `legacy/prototype/动物基础动作GIF/` 已有 4 只宠物 × 7 个动作 = 28 个 GIF，动作名与契约白名单一一对应、四只画风统一、真透明底（四角 alpha=0）；本轮只把小狗 7 个动作转成 512×512 / 12 帧 / 83 ms / q70 的动画 WebP，其余 3 只留作备用。源 GIF 单文件 0.8–4.7 MB，直接引用会拖垮首屏，因此必须转码，不能原样引用。
13. **运行副本放 `apps/web/assets/pet-ui/`，不放 `content/assets/pet-ui/`**。`dev-server.mjs` 只服务 `apps/web` 内的路径（带目录穿越防护），放两份会多出约 5.6 MB 重复文件；`content/assets/pet-ui/` 只保留美术需求单与素材登记表，来源与转码参数写在登记表里。
14. **贴图是增强而不是依赖**。贴图加载失败只收起图片并提示"退回纯文字"，主流程（聊天/建议/任务/积分）不依赖任何图片；`tests/pet-assets.test.mjs` 同时断言了 `load`/`error` 两个分支、白名单外的动作不猜路径、贴图目录必须是相对路径、单文件不超 300 KB。
15. **不把来源不明的素材写成"原创"或"已授权"**。登记表如实写"旧原型历史素材（作者未提供）…仅在仓库内复用"，`status` 列写明"已接入网页（来源未提供）"；能否进提交材料由 A 按提交清单决定。

## 校园地图（2026-10-16）

16. **地图运行副本只放 `apps/web/assets/campus/` 一份**（同贴图口径）：`dev-server.mjs` 只服务 `apps/web` 内的路径且防目录穿越，`content/assets/campus/` 只放说明与登记表，避免约 300 KB 重复文件。单文件预算 400 KB（成品 315.3 KB）：地图要铺满约 950 px 的内容宽度，源宽留 2000 px 给高 DPR 屏，压到 300 KB 需要把 q 压到 70 以下、画面水彩味会明显发脏。
17. **AI 标注优先写在 HTML 静态文本里，不靠脚本注入**：`alt` 与 `figcaption`（`#campus-map-note`）直接写明"AI 生成示意插画（源图由千问 AI 生成）""非精确导航，不代表真实校区地标的位置与距离"，这样即使 JS 失败也不会丢掉标注；JS 只负责加载失败的降级与地标交互。
18. **地标点击复用已有 `scene_enter`，契约零改动**：点击地标＝设置当前场景并调用现成的 `enterScene()`，与"进入场景"按钮同一路径、同一校验；场景值必须先过新增的 `view.knownScene()`（只认 `SCENE_LABELS` 里 `Object.hasOwn` 的键），白名单外的一律只打日志、不发请求。顺带把 `petAssetFile` 也改成 `Object.hasOwn` 判断：原来 `PET_ASSET_FILES[action] ?? null` 会把 `constructor`/`toString` 这类原型链名字当成合法文件名（虽然服务端不会这么返回，但不该留这个口子）。
19. **不把 AI 生成图当校园事实**：源图自带"千问AI生成"水印与 AIGC 元数据，所以登记为"AI 生成／来源未提供"，绝不写成手绘或实拍；页面明写"非精确导航""站牌数字属 AI 装饰"，校区与地标位置、距离一律未核实、不进材料。
20. **成品只做一次有损压缩**：成品由 Pillow 从源 PNG 重跑同一管线（去水印／擦文案／裁边框／缩放）并附带 XMP 写出，随后校验 `VP8 ` 图像数据 sha256 与已目视验收的版本完全一致（`acce3851d120c1a5`），所以 6 倍放大的目视结论可以直接沿用，不存在"再压一次导致画质与验收版本不一致"的问题。

## 连接状态可见性（2026-10-16 缺陷修复）

21. **连接失败必须显示在用户正在看的地方**。起因：用户点"连接服务"后页面毫无变化，误以为按钮没反应——实际原因只是 mock 服务没启动（8787 未监听），而失败信息原来只写在页面最下面的第 8 节"错误与重试"，顶部徽标始终是"未连接"。
    改法（只动展示层，契约与接口零改动）：
    - 新增 `state.connect`（`idle|pending|ok|failed`），失败时同时写 `state.mode = 'error'`；顶部徽标新增 `连接失败`（红底），按钮正下方的 `#health-text` 用新增的 `view.connectStatusView()` 显示"连接失败：<原因>｜请确认已运行 npm run mock（127.0.0.1:8787）…详细错误与重试按钮在第 8 节"，并用 `data-tone` 配色；状态行加 `role="status"/aria-live="polite"`。
    - 文案里带上错误码（如 `[NETWORK_ERROR]`），并明确写出下一步命令，避免"只是说了失败但不知道怎么办"。
    - `view.sendLocked` 收紧为"未连接/失败/等待都锁住发送"，与提示语一致。
    - **不猜不编**：失败状态只由真实请求结果驱动，连接成功才显示"已连接 <地址>"；失败时绝不显示"模拟 mock"。
    - **10-16 下午更正（重要）**：当时把成因写成"失败信息只在第 8 节"是**不完整**的。用户截图里的徽标与提示恰好等于 `index.html` 里的静态初始文案，说明浏览器根本没执行 JS——真正的根因是 `index.html` 缺 `<script>` 标签（见第 23 条）。本条修的失败可见性是真问题、也保留，但它并不能解释用户当时看到的现象。
22. **测试用 DOM 桩执行真实 `app.js`，而不是只做字符串断言**。新增 `tests/app-flow.test.mjs`：最小 DOM 桩 + 真实起 `tools/mock-api.mjs`（随机端口）+ 真实 HTTP，覆盖①连接失败可见（回归本次缺陷）②连上后"地标选场景 → 建议 → 接受 → 完成"整条链路与宠物贴图换图 ③服务中途停掉后发送显示可重试失败。
    代价与边界：这是 DOM 桩模拟，**不是真实浏览器**，因此不覆盖布局/滚动/CSS；真实浏览器走查仍记为"未验证"。
    过程中踩到并已修的坑，写下来防止重犯：包装 `globalThis.fetch` 前必须先 `bind` 原函数，否则包装函数内部再调 `fetch` 会指向自己直接爆栈；桩的 `textContent` 必须只放自身文本，否则 `textContent +=` 会把整棵子树重写一遍；`server.close()` 要配 `closeAllConnections()`，否则 keep-alive 连接会让测试进程挂住。

## 页面必须真实加载脚本（2026-10-16 真根因：页面一直是静态 HTML）

23. **`index.html` 必须用相对路径以模块方式加载 `./app.js`，否则整页不会跑 JS**。事实经过：10-16 用户反馈"点连接服务/进入场景没反应"，截图里徽标是"未连接"、提示是"尚未连接到服务。"、状态行空白——这三条恰好都是 `index.html` 里写死的初始文案，即浏览器从未执行 `app.js`。`git show 556c4a6:apps/web/index.html` 确认第一个提交（页面骨架 v1）里就没有 `<script>` 标签，所以这不是回归，而是**从 v1 起页面一直是静态 HTML**。
    成因：`tests/page-safety.test.mjs` 原断言写成 `/<script[^>]+src=/.test(pageHtml) === false`——本意是"不许引外部 CDN 与第三方脚本"，实际把所有 `<script src>`（含本仓库本地模块）一起禁掉了，于是"让测试通过"的方式就是把脚本标签删掉。
    改法：
    - `index.html` 在 `</body>` 前加 `<script type="module" src="./app.js"></script>`。
    - 断言改成按**意图**判断：`src/href` 属性里不许出现 `http(s)://` 或协议相对 `//host`；正文里给用户看的 `http://127.0.0.1:8787` 提示文本不算外链（查整页"不许出现 http"会误伤）。
    - 新增守门用例：①必须恰好一个脚本标签、`type="module"`、`src="./app.js"`、位于 `</body>` 前；②页面引用的本地脚本/样式/图片都真实存在（`existsSync`）；③`tests/app-flow.test.mjs` 里用**真实 HTTP** 起静态服务器取 `/`、提取脚本地址、取回并校验 200 与 `text/javascript`。
24. **教训：反例断言要写在"意图"上，不要写在"写法"上；"点了没反应"先怀疑 JS 没跑**。上一条同族风险是"页面引用了不存在的文件"，这次一并加了 `existsSync` 校验。判断口径：如果用户截图与 `index.html` 的静态初始状态完全一致（徽标/提示一字不差），问题就在"脚本没执行"，而不是"状态没渲染"——这时不该去改渲染逻辑。
    代价与边界：这三条测试只能证明"页面会去加载脚本、脚本能取到"，**不能证明真实浏览器里交互一定生效**；真实浏览器点击走查当时记为"未验证"（本机无无头浏览器）。→ 已由 2026-10-16 晚第 29–31 条补上：本机 Edge 155 可用无头模式，走查工具已入库；也正因为补了这一层，才发现 Node 测试全绿时页面仍连不上服务。

## 宠物形象：4 只全部接入（2026-10-16）

25. **旧原型已有的 4 只宠物素材一次接完，不再去 GitHub 找图**。依据：`legacy/prototype/动物基础动作GIF/` 的 4 只 × 7 动作与契约白名单完全对应、画风统一、真透明底；靠"能对上白名单动作"这一点就胜过任何外部桌宠包（外部素材普遍缺 sleep/eat/roll，映射不上）。队长 10-16 确认"现有素材能用的直接用、不用再纠结来源"，因此本轮把其余 3 只（小龟/猫咪/小羊）也转码接入。
    改法与守门：
    - `lib/view-model.mjs` 新增 `PET_KIND_LABELS`（4 个形象）与 `DEFAULT_PET_KIND='dog'`，`PET_ASSET_FILES` 改为按 `形象.动作` 生成的 28 条映射；`petAssetFile(action, kind)` 必须**两个白名单都命中**才返回文件名，否则 `null`（不传 `kind` 时保持旧行为＝小狗，历史调用点零改动）。
    - 本地存储里的形象、下拉选中值一律过 `knownPetKind()`，白名单外回落默认小狗——存储被手改或留着旧值也不会把页面搞成"没有宠物"。
    - 换图判重 key 从"文件名"改成"形象/文件名"，避免将来只比文件名时换不掉图。
    - 用户换形象时用 `state.petPreview` 先给一眼该形象的 `idle` 贴图，**不发任何请求**；收到服务响应后仍以 `pet_action` 为准。理由：切换后毫无反馈会和"点了没反应"同族（DECISIONS 第 21/24 条）。
26. **素材体积取舍：一次只加载 1 张，所以按"单张 ≤300 KB"控制，不追求总包体**。28 张合计 5.62 MB（仓库体积约 +5.6 MB），但页面任一时刻只用 1 张、且都是本地相对路径、无网络等待。不做雪碧图/帧图集：桌宠贴图是逐动作独立循环的透明动画，图集只是把体积换个地方放，还会让"按动作取图"的白名单逻辑变复杂。
27. **拍立得相框、`3334.jpg`、`.ogg` 实测后本轮不接入（有数据、不是嫌麻烦）**。相框 4 张是竖版（604×953 / 1163×1819 / 1190×1848 / 1159×1742，约 5:8），透明像素占 61–64%、四角与中心透明；而宠物贴图是 512×512 正方形，页面本轮也没有相机/合拍流程（摄像头按第 10 条只做拒绝授权演练），硬套会像错位，不如留在 ART_BRIEF 里注明"做合拍时请给 1:1 窗口版"。`3334.jpg` 是 1204×1484 RGB 无说明彩图，来源与用途都说不清；两个 `.ogg` 约 2.2 MB / 0.95 MB、内容不明。**宁可少接，也不猜素材用途。**
28. **favicon 用同一张贴图派生，不新找图**：`tools/convert-legacy-pets.py --favicon` 从 `pet-dog-idle.webp` 首帧裁切、补成正方形、按 512→32 的边长梯度压，直存 RGBA 超预算就先做调色板量化（255 色 + 透明），产出 `apps/web/favicon.png`（512×512 调色板 PNG 27.8 KB，需求单预算 50 KB）。`index.html` 用相对路径 `<link rel="icon">` 引用，`pet-assets.test.mjs` 守 PNG 签名、正方形、边长 192–512、体积与"页面确实引用本地 favicon"。
    过程记录：第一版只按边长降级，落到 192×192（44.3 KB）才发现"小图也能很大"；改为优先量化后保住 512。经验写在这里，避免下次再把"降边长"当第一手段。

## 真实浏览器走查（2026-10-16 晚，B）

29. **`this.fetchImpl(...)` 让浏览器原生 fetch 抛 `Illegal invocation`——页面在任何真实浏览器里都连不上服务**（Node 测试 57/57 全绿也测不出来）。事实经过：用本机 Edge 155 无头打开 `http://127.0.0.1:5173`，状态行报 `[NETWORK_UNREACHABLE] 连不上服务`，但同一页面里执行 `fetch('http://127.0.0.1:8787/health')` 返回 200，且 `performance.getEntriesByType('resource')` 中**没有任何 8787 的请求**——说明请求根本没发出去。用 CDP 复现调用方式：`const h = { f: window.fetch }; h.f(url)` → `TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation`。
    成因：浏览器的 `fetch` 是 WebIDL 操作，receiver 必须是 `Window`；`lib/api.mjs` 写的是 `await this.fetchImpl(...)`，receiver 变成了客户端对象。Node 的 `fetch` 不校验 receiver，所以 DOM 桩、真实 HTTP 单测都发现不了，只有真实浏览器才暴露。
    改法：`const fetchImpl = this.fetchImpl; await fetchImpl(...)`（无 receiver 调用）；`apps/web/tests/api.test.mjs` 新增回归用例，用一个"`this !== undefined` 就抛同样 TypeError"的 stub 模拟浏览器语义，这条用例在旧写法下必失败。
30. **真实浏览器走查工具入库，不再靠"源码级/HTTP 级"推断交互**：`apps/web/tools/browser-walkthrough.mjs`（零第三方依赖，用 Node 内置 `WebSocket` 说 CDP）自动走"连接 → 地图点图书馆 → 收到建议 → 接受 → 完成 → 换形象"，逐屏存 PNG 并额外截宠物区特写，结束时打印 `Network.loadingFailed` 与 `Log.entryAdded`，即"零网络失败/零控制台错误"的证据。用法与产物见 `README.md`，2026-10-16 晚 Edge 155 实测全绿。
31. **首屏宠物默认待机（修订第 25 条"只给换形象预览"）**：走查截图显示，收到服务响应前宠物区是一个空框——一个宠物应用的默认画面里没有宠物。改为 `state.petPreview` 默认 `true`，用 `idle` 贴图占位，标签写"动作：待机（默认，尚未收到服务响应）"、说明写"默认待机（服务还没返回动作）"；服务返回 `pet_action` 后照旧覆盖。原则不变：**默认值只是占位，不冒充服务返回的动作**，也不因此发任何请求。

- 真实服务的错误码表是否与 mock 一致（当前依赖 `NO_LOCAL_SESSION`/`TASK_NOT_FOUND`/`ORIGIN_NOT_ALLOWED`/`INVALID_EVENT` 等命名）。
- live 服务是否同样校验 `preferences.remember === false`；若允许 `true`，需要同步授权与删除路径再开。
- 校园名称与地标真实性：地图是 AI 生成示意插画，若要在地图或材料里点名具体校区/地标，需要先由 A 核实来源；当前口径只写"示意"，不写事实。
- 真实截止时刻、飞书模板与评审访问方式（B 尚未核实，见 `docs/handoffs/B/current.md`）。
